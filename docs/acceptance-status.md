# 基础要求验收证据清单

更新：2026-09-22。依据 [赛题原文](../problem.md)、[正式原型说明](../README.md)和
[实验记录](../experiments/README.md)。这里的“通过”只指记录中的具体场景；
未把脚本实验等同于真实 Agent 或完整赛题验收。

| 基础要求 | 已有证据 | 状态与缺口 |
| --- | --- | --- |
| 多 Agent 进程采集与归属 | 单监控器双组 `sleep` 的 exec/exit 交错且未串组；双组文件/网络混合工作负载归属正确；三组资源联合异常证据隔离。 | **受控场景通过**。尚未运行两个真实 Codex Agent 并发，也未验证更多实例或根进程退出后仍存活的后代。 |
| 文件操作及真实路径 | BPF LSM 的 FILE_OPEN、FILE_UNLINK_ATTEMPT 在脚本中与目标绝对路径一致；真实 Codex 经 `cat` 打开只读 `marker.txt` 的 FILE_OPEN 已记录。 | **受控场景及单个真实 Agent 读取通过**。unlink 是删除前尝试，不证明结果；失败 openat 是还原尝试路径，不是真实规范路径；openat2/rename 等未覆盖。 |
| 网络目标 IP/端口 | 受控脚本中 IPv4 成功、失败及 IPv6 成功目标均核对；真实 Codex 记录了同组线程的 443 端口 CONNECT_RESULT。 | **受控场景及单个真实 Agent 连接观测通过**。真实 Agent 的非阻塞 `ret=-115` 只表示 EINPROGRESS，不能据此判定连接最终成功；连接目标不等同于一次模型 API 请求。 |
| 非预期 Shell、敏感读取、工作区外删除 | 正式 detector 的三条规则均有 sudo 端到端脚本正例，且有相应未命中的对照；告警带时间、PID/TID、agent_id、cgroup_id、目标及证据。 | **受控脚本通过**。尚无真实 Codex 触发规则的受控验证；敏感规则证明可读方式打开，不证明实际读取内容或真实授权状态。 |
| 资源/逻辑异常 | 5 次同目标 ENOENT 与 cgroup CPU 高占用联合触发一次告警；三 Agent 对照中，单独重复失败或单独高 CPU 不触发联合告警。 | **受控脚本通过**。这是重复无意义文件活动加 CPU 的一种联合证据；未覆盖高频 API、重复 Prompt 或更一般的逻辑死循环。 |
| 告警归因日志 | 正式规则日志含单调时间戳、PID/TID、目标、agent_id、cgroup_id 和 evidence；脚本事件与告警字段已逐项对齐。 | **已有基础归因证据**。尚不能从特定 Prompt/Response 精确回溯到操作；该因果关联也是赛题进阶方向。 |
| 内核版本与性能 | 开发机记录内核 7.0.0-31-generic；VirtualBox 中 N=100 文件抽样 15 对测试，map 合并后总开销逐对中位数 8.08%，p25/p75 为 6.02%/15.29%。 | **开发机初测，未达 5% 参考指标**。默认全量模式开销更高；N=100 可能漏掉普通打开，且与敏感目录规则互斥。尚无真实 Linux 机器性能测量或 5.15 实机兼容验证。 |

## 下一步验证优先级

1. 用现有单监控器运行两个真实 Codex Agent，核对各自 cgroup、文件和网络事件；
   先设计短任务与预算，再运行，以免无目的消耗模型额度。
2. 在专用测试目录中验证真实 Codex 触发一条安全规则，并保留目标文件和告警的
   同时间戳、PID/TID、agent_id 与 cgroup_id 证据。只选择无害、可复现的操作。
3. 整理一个可复现演示流程和预期输出；如能取得真实 Linux 机器，再复测开销。

HTTPS 明文、Prompt/Response 捕获及精确因果关联、协作/竞争异常属于进阶方向，
当前不作为已有能力陈述。`--hide-runtime-noise` 只减少普通文件事件的展示，
不减少内核采集开销，也不能代替完整审计日志。
